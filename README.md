# Task Manager — приложение для управления задачами

**Версия документа:** 1.0  
**Статус:** Требования разработаны (Лабораторная работа №1)

---

## 1. Введение

### 1.1. Цель разработки
Создать веб-ориентированную систему для управления личными и командными задачами, которая обеспечивает:
- удобное планирование рабочего дня;
- прозрачное распределение задач между участниками команды;
- доступ с любого устройства через браузер.

### 1.2. Формулировка задачи
Разработать веб-приложение, позволяющее пользователям:
- регистрироваться и авторизоваться;
- создавать, редактировать и отслеживать задачи;
- назначать задачи другим пользователям;
- фильтровать и сортировать задачи по различным критериям;
- получать уведомления о приближающихся дедлайнах.

### 1.3. Исходные данные
- **Технологический стек:** Python 3.9+, Django (или FastAPI), PostgreSQL, HTML/CSS/JavaScript.
- **Хранение данных:** реляционная СУБД PostgreSQL.
- **Целевые платформы:** веб-браузеры (Chrome, Firefox, Safari, Edge).

---

## 2. Бизнес-требования

1. Приложение должно сокращать время на планирование задач до 5 минут в день.
2. Продукт должен обеспечивать командную работу (до 10 человек в одной группе).
3. Интерфейс должен быть интуитивно понятным и адаптивным (работать на экранах от 1280×720).
4. Базовая версия должна быть бесплатной, расширенный функционал (интеграция с календарями) — опционально.

---

## 3. Пользовательские требования

### 3.1. Целевая аудитория
1. **Студенты и преподаватели:** для планирования учебных проектов и дедлайнов.
2. **Команды разработчиков (2–10 человек):** для распределения задач в рамках курсовых или стартапов.
3. **Частные лица:** для ведения личных дел и рутины.

### 3.2. Сценарии использования

| Действующее лицо | Действие |
|---|---|
| Пользователь | Регистрируется в системе (логин/пароль). |
| Пользователь | Создаёт задачу: название, описание, дедлайн, приоритет, статус. |
| Пользователь | Назначает задачу другому участнику команды. |
| Пользователь | Просматривает все задачи в виде списка или канбан-доски. |
| Пользователь | Изменяет статус задачи («Новая» → «В работе» → «Выполнена»). |
| Пользователь | Фильтрует задачи по статусу, приоритету, исполнителю. |
| Пользователь | Ищет задачу по названию или описанию. |
| Пользователь | Получает уведомление за 1 час до дедлайна. |
| Пользователь | Редактирует или удаляет задачу (с подтверждением). |

## 4. Функциональные требования

### 4.1. Управление пользователями
1. **Регистрация** — форма с полями: логин, email, пароль (подтверждение).
2. **Авторизация** — вход по логину/паролю, сессия сохраняется.
3. **Выход из системы** — завершение сессии.

### 4.2. Управление задачами (CRUD)
1. **Создание** — форма с полями: название (обязательно), описание (опционально), дедлайн (календарь), приоритет (Низкий/Средний/Высокий), статус (Новая/В работе/Выполнена), исполнитель (выбор из списка пользователей).
2. **Просмотр списка** — таблица с колонками: Статус, Название, Дедлайн, Приоритет, Исполнитель.
3. **Просмотр деталей** — клик по задаче открывает карточку с полной информацией и историей изменений.
4. **Редактирование** — кнопка «Редактировать» открывает форму с заполненными полями.
5. **Удаление** — кнопка «Удалить» с диалогом подтверждения.

### 4.3. Управление статусами и состояниями
1. **Смена статуса** — выпадающий список или drag-and-drop на канбан-доске.
2. **Авто-определение просрочки** — если текущая дата > дедлайна, а статус не «Выполнена», задача подсвечивается красным.
3. **История изменений** — логирование всех действий с задачей (кто и когда изменил статус).

### 4.4. Фильтрация, сортировка и поиск
1. **Фильтры** — по статусу, приоритету, исполнителю, проекту.
2. **Сортировка** — по дедлайну, приоритету, дате создания (возрастание/убывание).
3. **Поиск** — по названию и описанию (мгновенно, задержка < 500 мс).

### 4.5. Командная работа
1. Назначение задачи одному или нескольким исполнителям.
2. Отображение задач, назначенных текущему пользователю, в отдельном разделе «Мои задачи».
3. Возможность комментировать задачи (опционально).

### 4.6. Уведомления
1. Локальные уведомления в браузере (через Notification API) за 1 час до дедлайна.
2. Список просроченных задач на главном экране.

### 4.7. Хранение данных
1. Все изменения (создание, редактирование, удаление) немедленно сохраняются в PostgreSQL.
2. Резервное копирование базы данных — ежедневно.

## 5. Нефункциональные требования

### 5.1. Требования к надёжности
- Приложение должно корректно обрабатывать ошибки ввода (показывать понятные сообщения, а не падать).
- При обрыве соединения несохранённые изменения должны сохраняться в виде черновика (localStorage).
- Время восстановления сервиса после сбоя — не более 15 минут.

### 5.2. Требования к производительности
- Загрузка главной страницы — не более 3 секунд.
- Открытие списка из 500 задач — не более 1 секунды.
- Поиск/фильтрация — задержка менее 500 мс.
- При одновременной работе до 100 пользователей сервер должен отвечать за 2 секунды.

### 5.3. Условия эксплуатации
- Программа работает в стандартных офисных/бытовых условиях.
- Серверное обслуживание — 1 администратор.
- Пользователи должны обладать базовыми навыками работы с браузером.

### 5.4. Требования к совместимости
- **Сервер:** Linux/Windows, 2+ ядра CPU, 4+ ГБ ОЗУ, 20+ ГБ диска.
- **Клиент:** любой ПК с современным браузером (Chrome, Firefox, Safari, Edge).
- **Мобильные устройства:** адаптивный дизайн под экраны от 360px ширины.
- **Браузеры:** последние 2 версии.

### 5.5. Требования к интерфейсу (UI/UX)
- Главное окно содержит: заголовок, навигационное меню, список задач, кнопку «Создать задачу».
- Основные разделы навигации: «Все задачи», «Мои задачи», «Доска», «Настройки».
- Поддерживаются светлая и тёмная темы.
- Интерфейс выполнен на русском языке (с возможностью переключения на английский).
- Диалоговые окна создания/редактирования — модальные.
